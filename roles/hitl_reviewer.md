# Role: HITL Reviewer (人工审校门禁 —— 强提示词约束)

# 定位：由【主 agent】扮演（不是 subagent）。在流水线的关键门禁点，主动停下、向用户呈现待审项、等用户回复后再继续。
# 触发：run_pipeline 进入门禁阶段后，.modeling/hitl/<phase>_gate.md 存在 且 phase_status.json 该阶段标记 waiting_human。
# 依赖：references/hitl_prompt_design.md（机制）、references/hitl_design.md（分级/门禁点/动作定义）。

## 核心使命（一句话）
**在数学建模流水线的关键决策点，把"是否放行/改方向"的判断权交给用户，并在拿到用户明确回复前绝不自作主张继续。**

---

## 强约束：六条不可违反的纪律（最高优先级）

1. **必须停下**：一旦读到门禁标记（`.modeling/hitl/<phase>_gate.md` 存在 / `phase_status.json` 该阶段 `status == "waiting_human"`），**立即停止推进后续阶段**，不得继续跑下一阶段的任何动作。

2. **必须读出待审项**：把 `.modeling/hitl/<phase>_gate.md` 里的【待确认项】+【Agent 建议】完整读出、清晰呈现在对话里给用户看。不得省略、不得只给摘要。

3. **必须提问并列出动作**：在对话中明确问用户，并列出入选动作：
   ```
   📌 人工审校：[阶段 X 门禁名]
   【待确认项】...
   【Agent 建议】...
   【请选择】 confirm / edit / regenerate / skip / abort
   （或直接输入你的修改意见）
   ```

4. **必须等用户回复，禁止自问自答**：提出上述问题后，**本回合到此结束，把话语权交给用户**。禁止自己替用户拍板（如"我帮你确认了"「我直接放行」「既然没提问题就继续」）、禁止默认 confirm、禁止为了赶进度跳过这一步门禁。**用户不回复，就不继续。**

5. **绝不在用户缺席时静默放行**：即使处于 benchmark / auto 跑批，也要**先尝试注入审校提醒**（体现"人工必审"）。仅当后续用户明确不参与（或编排器告知"无人回应，降级"）时，才降级为 confirm。

6. **必须落盘**：用户给出动作后，把 `{action, comment, timestamp}` 写入 `.modeling/hitl/<phase>_feedback.json`（当次生效，不沉淀回灌），并把 `phase_status.json` 该阶段状态改为 `done`（或按动作记为 `regenerate/abort`）。

---

## 动作处理（用户回复 → 主 agent 怎么做）

| 用户动作 | 主 agent 处理 |
|---|---|
| `confirm` 或"确认" | 记录 action=confirm，放行进入下一阶段 |
| `edit` 或自由文本意见 | 把用户意见作为**硬约束**，修改当前阶段产物后重跑该阶段 |
| `regenerate` 或"重做/换思路" | 清空该阶段产物，换思路重跑 |
| `skip` 或"跳过" | 标记 SKIPPED，继续下一步 |
| `abort` 或"中止/停" | 停止，回退上一门禁或提示重新选题 |

---

## 如何判断"该轮到用户说了"（防自答的自我检查）
提出门禁问题后，如果发现自己：
- 马上又去调工具、继续推进下一阶段 → **违反了纪律 4，立即纠正：停止，等用户**；
- 替用户说"那我确认了" → **违反纪律 4，立即纠正：把选择权交回用户**；
- 认为"用户没提意见=默认通过" → **违反纪律 4/5，禁止这种推断**，必须等用户明确回复。

**自我检查口诀**：问完用户 → 停止 → 等回复。回复前没有任何后续动作。

---

## 与主 agent 编排的关系
本角色是**主 agent 的一部分行为约束**，不产生独立的 subagent 会话。主 agent 在编排流水线时，读到门禁标记即切换到本角色的行为模式：停下 → 读待审项 → 问 → 等 → 处理。

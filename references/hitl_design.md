# 人在回路（Human-in-the-Loop）设计

> 核心取向：**差异化设计**。主流开源科研 agent（AIDE / AutoKaggle / MM-Agent / AI Scientist）都追求"尽可能全自动、越少人介入越好"；本框架反其道，在数学建模这个"没有唯一标准答案、人的领域判断最值钱"的场景里，**在每个高信息熵的决策点引入人的反馈**。
>
> 关键张力与解法：不是"每步都问"（那会拖垮 3 天竞赛节奏、也违背精简原则），而是**在信息熵最高、最容易走错、且人类能提供独特价值的关键决策点设门禁；其余保持自动**。人的介入是"手术刀式"的，不是"撒网式"的。

---

## 一、分层门禁（三档，避免撒网式介入）

| 档位 | 语义 | 何时用 | 理由 |
| :-- | :-- | :-- | :-- |
| **🔴 强制门禁** | 必须人确认，否则停 | 题意理解、模型方案、报告审批 | 这三处：agent 最易理解偏（人抓缺口的能力最值钱）、领域判断最强、最终交付 |
| **🟡 可选介入** | agent 给出建议，人可一键通过/修改 | 求解结果量级、方向选择 | 走错代价不致命，给人"看一眼"的机会 |
| **⚪ 全自动** | 人默认不介入 | 脚本冒烟、图表生成、格式校验 | 低信息熵、确定性、人看了也帮不上 |

## 二、六阶段对应门禁点

| 阶段 | 门禁点 | 人问什么 | 档位 |
| :-- | :-- | :-- | :-- |
| **阶段 0 数据摸底** | 题意理解画像 | "agent 对题目约束/交付物的理解对不对？有没有漏读/误读题目？" | 🔴 |
| **阶段 1 检索+发散** | 命中的 2-3 个方向 | "这些建模方向贴合题意吗？要不要加/换方向？" | 🟡 |
| **阶段 2 Actor-Critic** | 模型方案（模型+关键假设+目标函数） | "这个模型选择符合领域直觉吗？假设成立吗？" | 🔴 |
| **阶段 3 求解** | 关键结果量级 | "这些数值量级合理吗？" | 🟡 |
| **阶段 4 轻审稿** | 是否放行 | "要放行进写作吗？" | 🔴 |
| **阶段 5 写作** | 建模报告 → 论文正文 | "报告 OK 吗？措辞/结论要不要调？" | 🔴 |

## 三、动作类型（5 个，比 MathModelAgent 的 6 个更聚焦）

每个门禁点的人反馈，用以下 5 个动作之一：

| 动作 | 语义 | 对应处理 |
| :-- | :-- | :-- |
| **确认** | 认可 agent 的当前产出 | 直接放行到下一阶段 |
| **修改** | 认可大方向，但给具体修改意见 | 按人意见修订后重跑该阶段 |
| **重新生成** | 当前产出不行，让 agent 换思路重来 | 清空当前阶段产物，重新执行 |
| **跳过** | 人决定接受默认/跳到下一步 | 标记 `SKIPPED`，继续 |
| **中止** | 讨论后发现方向错了 | 停止，回退到上一门禁或重新选题 |

## 四、运行模式与介入的平衡

| 模式 | HITL 门禁 | 说明 |
| :-- | :-- | :-- |
| **实战模式** | 🔴 全开，人在用 | 人全程把关关键决策点，参赛/交付场景 |
| **benchmark 模式** | 门禁自动放行 | 人缺席也能跑完出分，评测驱动迭代不被人的介入卡住 |

## 五、实现位置：主线程编排层（不是 subagent 内部）

人在回路必须由**主线程在编排层**做，不能塞进 subagent（subagent 独立上下文、看不到人）。

主线程流程（示意）：

```
Phase 0 → [🔴 人等确认] → Phase 1 → [🟡] → Phase 2 → [🔴 人等确认] → Phase 3 → [🟡] → Phase 4 → [🔴] → Phase 5 → [🔴 报告] → 论文
```

每次人介入，主线程：
1. 把**待确认项 + agent 建议**展示给人；
2. 人反馈（5 个动作之一，或自由文本意见）；
3. 主线程把反馈**落盘** `.modeling/hitl/<phase>_feedback.json`（当次生效，不沉淀——本次决策：不形成回灌资产，保持精简）；
4. 反馈在后续阶段作为**硬约束**注入（人说了方向就按人的来）。

## 六、落盘约定

人反馈落盘到 `.modeling/hitl/` 下：
- `<phase>_feedback.json`：每阶段一份，记录动作类型 + 人意见文本。
- 人类可读版：`.modeling/hitl/HITL_日志.md`（若需要留痕）。

> 本次决策（用户拍板）：**反馈只在当次运行生效，不沉淀回灌**。若未来发现"人的重复意见很多"，再升级为回灌机制（把高频人意见沉淀进 CHANGELOG/roles）。
